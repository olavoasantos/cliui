# Write Docblocks

Write or improve JSDoc/TSDoc docblocks on public exports. Reference documentation is auto-generated from these docblocks, so their quality directly determines the quality of the API reference.

## Input

The user specifies a scope — specific files, directories, packages, or `all`. If no scope is given, find all public exports missing docblocks.

## Rules

### What Gets a Docblock

Every public export — anything re-exported from `src/index.ts` — must have a docblock:

- Classes (the class itself + all public methods and properties)
- Functions and utilities
- Interfaces and type aliases
- Constants
- Components (the component function + its props type)
- Hooks
- Guards
- Services (the class + all public methods)
- Data sources (the class + all public signals)
- Errors

### What a Docblock Contains

**Description** — What this thing is and why you'd use it. Lead with the most important information. One to three sentences for simple exports; a short paragraph for complex ones.

**`@param`** — One per parameter. Describe what the parameter does, not its type (TypeScript handles that). Note constraints, defaults, and edge cases.

**`@returns`** — What the function returns and under what conditions. Skip for void functions.

**`@template`** — One per generic parameter. Describe what the parameter represents and any constraints. Every generic on a public export must have this tag.

**`@throws`** — Each exception the function can throw and when. Use the error class name.

**`@example`** — A minimal, illustrative usage example. Include when the usage isn't obvious from the signature. Keep it short — this is reference, not a tutorial.

**`@see`** — Cross-references to related exports, guides, or external resources.

**`@deprecated`** — When applicable, include what to use instead.

### What a Docblock Does NOT Contain

- **Type information already in the signature.** Don't write `@param name - string - The name` when the type is already `name: string`.
- **Implementation details.** Don't describe how it works internally. Describe what it does.
- **Obvious descriptions.** If `getName()` returns the name, don't write a docblock that says "Gets the name." Add value — when would you call this? What name? In what format?
- **Issue IDs or tracking references.** Never reference milestone or issue identifiers.
- **AI attribution.** No "Generated by..." comments.

### Style Rules

- **Present tense, active voice.** "Creates a new instance" not "This method will create a new instance".
- **Start descriptions with a verb** for functions/methods ("Returns...", "Creates...", "Validates...").
- **Start descriptions with a noun** for types/interfaces/classes ("A reactive store that...", "Configuration for...").
- **No filler.** No "This function is used to..." — just say what it does.
- **Be precise about nullability.** If something can return `null` or `undefined`, say when and why.
- **Document error conditions.** If a function throws, document when. If it returns a result type, document failure cases.

## Process

1. **Identify scope.** Determine which files/exports need docblocks.
2. **Read each file.** Understand what the export does by reading the implementation, tests, and any existing documentation.
3. **Write docblocks.** Follow the rules above. Write for the consumer — someone reading the generated reference docs who wants to know what this does and how to use it.
4. **Verify.** Run `pnpm run check` to ensure docblocks don't introduce any issues (e.g., malformed JSDoc tags that break tooling).

### Component Props

```ts
/**
 * Props for the Button component.
 *
 * @see {@link ButtonVariant} for available visual styles.
 */
export interface ButtonProps {
  /** Visual style variant. Defaults to the primary style when omitted. */
  variant?: ButtonVariant | null;

  /** Size preset. Defaults to `'md'`. */
  size?: ButtonSize | null;

  /** Shows a pending state and disables interactions. */
  loading?: boolean | null;

  /** When provided, renders as an anchor element instead of a button. */
  href?: string | null;
}
```

### Generic Interface

```ts
/**
 * A named registry that stores and retrieves items by name.
 *
 * @template Item - The type of items stored. Must have a `name` property.
 */
export interface Registry<Item extends {name: string}> {
  /** Register an item. Duplicate names warn and overwrite. */
  register(item: Item): void;
  /** Retrieve an item by name. */
  get(name: string): Item | undefined;
}
```
